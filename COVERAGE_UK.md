# ДЗ №8: відповідність вимогам — напрям 1

Аудит зіставляє завдання з наявними перевірками. **Розгорнутий застосунок** —
тести Playwright проти AWS; **in-memory** — серверні тести .NET у CI з
підставною базою та поштою. Останні не доводять поведінку розгорнутого API.
Тести, які створюють бронювання, запускаються окремо через workflow dispatch.

## Рівень 1: перегляд групи

| Вимога | Покриття | Межа перевірки |
| --- | --- | --- |
| Бронювання, запрошення, страви та суми учасників | `confirmed-guests-live.spec.js`: два гості, статуси, страви, суми й загальний підсумок на екрані | Бронювання та кошики створюються через API; листи підтверджуються через UI |
| Загальна сума змінюється після зміни кошика | `GroupServiceTests.SnapshotIncludesPendingCartAndDecimalTotals`; UI-перерахунок після видалення гостя у `confirmed-guests-live.spec.js` | Окремої перевірки зміни загальної суми після редагування кошика гостем на розгорнутому UI немає |
| Непідтверджений учасник і учасник без страв | `confirmed-guests-live.spec.js` перевіряє обидва стани через розгорнутий API | Окремої перевірки напису для кожного стану на UI немає |
| Група без гостей | `confirmed-guests-live.spec.js`: жодного гостя та сума 0 | Власна сесія організатора залишається в масиві учасників |
| Лише організатор бачить список | Анонімний запит — `public.spec.js`; гостьовий токен і офіціант — `confirmed-guests-live.spec.js`; чужий власник — `HttpContractTests.SignedForeignOwnerGets403` | Чужий власник перевіряється in-memory |
| Група не існує | `confirmed-guests-live.spec.js`: 404 для автентифікованого організатора | Розгорнутий API |

## Рівень 2: спільне замовлення

| Вимога | Покриття | Межа перевірки |
| --- | --- | --- |
| Однакові страви об'єднуються, непідтверджені виключаються, статуси змінюються | `GroupServiceTests.SubmitMergesSubmittedCartsAndChangesBothStatuses` | Об'єднання та статуси перевіряються in-memory; виключення непідтвердженої страви — `owner-waiter-live.spec.js` на AWS |
| Офіціант бачить надісланий склад | `confirmed-guests-live.spec.js`, `owner-waiter-live.spec.js` | Реальні UI та API на AWS |
| Заборона порожнього/неіснуючого замовлення або бронювання | `GroupServiceTests.NoSubmittedSessionsReturns400WithoutChangingState`, `NoSubmittedDishesReturns400`, `MissingOrderReturns400`, `MissingReservationReturns404`, `MissingGroupReturns404` | In-memory; окремих перевірок усіх повідомлень на розгорнутому UI немає |
| Повторне підтвердження | `confirmed-guests-live.spec.js`: 400 або 409 на розгорнутому API; `GroupServiceTests.RepeatedSubmitDoesNotDuplicateItems` | Повернений код залежить від актуальної версії групи |
| Підтвердження не від власника | `confirmed-guests-live.spec.js`: офіціант отримує 403 | Розгорнутий API |

## Рівень 3: видалення гостя

| Вимога | Покриття | Межа перевірки |
| --- | --- | --- |
| Видалити одного з кількох, перерахувати суму | `confirmed-guests-live.spec.js`: склад, суми й UI до/після | Розгорнуті UI та API |
| Видалити підтвердженого гостя | `confirmed-guests-live.spec.js`: обидва гості підтверджуються через листи, одного видаляють | Реальні SES, UI та API |
| Видалити останнього гостя | `owner-live.spec.js`: гостей немає, загальна сума 0 | Сесія організатора залишається в масиві |
| Гість іншої групи — 400 | `owner-live.spec.js`: дві окремі групи | Розгорнутий API |
| Неіснуючий гість — 404 | `owner-live.spec.js` | Розгорнутий API |
| Видалення не від власника | Анонімний запит — `owner-live.spec.js`; офіціант — `confirmed-guests-live.spec.js` | Розгорнутий API; окремий чужий клієнт — `HttpContractTests.DeleteRejectsAuthenticatedNonOwnerWithoutChangingSnapshot` in-memory |
| Два гості → видалення → submit → офіціант | `confirmed-guests-live.spec.js` | Гостьові кошики створюються API, підтвердження, видалення, submit і перегляд виконуються через UI |

## Звітність та обмеження

- [Успішний спільний запуск усіх шести завдань CI](https://github.com/OverLordY/green-and-tasty-homework8/actions/runs/41427328345).
- [Успішний наскрізний тест із додатковими перевірками](https://github.com/OverLordY/green-and-tasty-homework8/actions/runs/41427771285).
- HTML/JUnit і TRX звіти зберігаються як артефакти CI. Для публічних UI-перевірок і сторінки групи організатора передбачено скриншоти при помилці; сторінки входу та гостьових посилань не фотографуються. Для помилки на інших етапах може не бути візуального матеріалу; trace/video вимкнені через приватні посилання.
- Тестові дані мають випадкові ідентифікатори; незавершені бронювання скасовуються. Надіслані бронювання не підтримують автоматичного скасування й залишаються в тестовому середовищі.
- Report Portal — окреме необов'язкове завдання із зірочкою; не налаштований.
